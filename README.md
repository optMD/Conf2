# apt-depgraph

Инструмент визуализации графа зависимостей пакета Ubuntu (формат apt).
Получение зависимостей выполнено без менеджеров пакетов и сторонних
библиотек.

## Общее описание

Инструмент читает зависимости пакета из файла `Packages.gz` репозитория
Ubuntu или из тестового файла графа и выводит узлы обхода на экран.

Что уже работает:

- разбор параметров командной строки и проверка их значений;
- скачивание `Packages.gz` по URL (`urllib`) и распаковка gzip через
  Go-программу `src/unpack`;
- разбор полей `Depends` и `Pre-Depends` (первая альтернатива `|`,
  версии и суффикс архитектуры отбрасываются);
- обход графа в ширину без рекурсии, устойчивый к циклам;
- тестовый режим с графом из файла вида `A: B C`;
- обратные зависимости (`--reverse`): рёбра обращаются в Java
  (`src/reverse`), затем тот же обход в ширину.

Что ещё не реализовано:

- вывод изображения в PNG через Graphviz и примеры для curl, wget, git,
  сравнение с `apt-cache depends` (этап 5). Параметр `-o` уже проверяется,
  но PNG пока не создаётся.

## Функции

| Функция | Что делает |
|---|---|
| `build_parser` | описывает параметры командной строки |
| `check_package` | проверяет имя пакета: в repo — имя apt, в test — одна заглавная буква |
| `check_source` | проверяет URL `http(s)` (repo) или существование файла (test) |
| `check_output` | проверяет расширение `.png` и существование папки вывода |
| `load_config` | разбирает аргументы, проверяет их и возвращает конфигурацию |
| `fetch_index` | скачивает `Packages.gz` через `urllib` и распаковывает его через `build/bin/unpack` |
| `parse_packages` | превращает текст `Packages` в словарь «пакет → зависимости» |
| `parse_dependency_field` | разбирает поля `Depends` и `Pre-Depends` |
| `load_test_graph` | читает тестовый граф из файла `A: B C` |
| `traverse` | обход в ширину без рекурсии, возвращает узлы и рёбра |
| `find_dependencies` | возвращает зависимости корня (или обратные) без самого корня |
| `reverse_graph` | обращает рёбра графа через Java-компонент `src/reverse` |
| `main` | запускает приложение и возвращает код завершения |

## Настройки

| Параметр | Значение |
|---|---|
| `package` | имя анализируемого пакета (в тестовом режиме — одна заглавная буква) |
| `source` | URL файла `Packages.gz` или путь к тестовому файлу |
| `--mode {repo,test}` | `repo` — реальный репозиторий (по умолчанию), `test` — граф из файла |
| `-o, --output FILE` | имя PNG-файла, по умолчанию `graph.png` (пока не используется) |
| `--direct` | вывести только прямые зависимости |
| `--reverse` | вывести обратные зависимости (кто зависит от пакета) |

Коды завершения: `0` — успех, `1` — ошибка выполнения (граф, сеть,
отсутствующий пакет), `2` — некорректный параметр.

## Сборка и тесты

```sh
./run.sh build   # собрать Go-распаковщик и Java-обращение рёбер в build/
./run.sh test    # собрать и прогнать тесты Go, Java и Python
```

Требуются Go, JDK (javac, java) и Python 3. Тесты Go лежат в `src/unpack`,
Java-тест — в `tests/reverse`, тесты Python — в `tests/cli`, тестовые
графы — в `tests/data`.

## Примеры использования

Тестовый граф с циклом:

```sh
./run.sh A tests/data/cycle.txt --mode test
```

Прямые зависимости `curl` из репозитория Ubuntu:

```sh
./run.sh curl https://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.gz --direct
```
